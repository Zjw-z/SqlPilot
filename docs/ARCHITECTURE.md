# SQLPilot 正式产品架构

## 核心原则

SQLPilot 采用“认证语义层优先、确定性编译优先、模型受控兜底”的架构。大模型负责把自然语言整理成结构化计划，不直接决定正式指标口径。

```text
自然语言对话
  → 需求计划（LLM）
  → 认证语义定义优先匹配
  → Schema混合检索与目录扫描
  → 字段、码值、时间、连接关系校验
  → 用户消歧与计划确认
  → 编译能力判定
      → 单事实表标准分析：确定性SQL编译
      → 多表或长尾：模型SQL受控兜底
  → AST白名单、计划一致性、EXPLAIN成本校验
  → PostgreSQL只读事务执行
  → 中文结果、分量纲图表、AI数据解读
```

## 语义对象

- `metric`：指标字段、聚合方式、单位和业务口径。
- `dimension`：维度字段、时间粒度和展示方式。
- `value_set`：业务标签到数据库码值的认证映射。
- `join`：表关系、连接字段、基数和重复聚合策略。

定义状态：

- `draft`：草稿，不影响正式查询。
- `certified`：已认证，优先覆盖模型和RAG绑定。
- `disabled`：停用。

## 确认学习边界

用户确认的字段绑定写入 `semantic_binding_observations`，用于统计常见选择和发现候选认证项，但不会自动升级为认证口径。只有管理员审核后才能写入 `semantic_definitions` 并标记为 `certified`。

## 编译器边界

`deterministic_ir_v1` 当前支持单事实表汇总、多个指标、直接维度、月份、同比、环比、过滤、排名和Top N。多表、明细查询及未支持表达式进入 `bailian_sql_fallback`，但仍必须通过同样的安全与计划校验。

运行响应通过 `evidence.sql_generation_strategy` 标识实际路径，禁止把兜底路径伪装成确定性编译。

## 准确性治理

正式验收分别统计：

1. 需求计划字段准确率。
2. Schema绑定Top-1及Top-k召回率。
3. 认证指标命中率。
4. 计划确认后一次执行成功率。
5. 与权威报表的结果对账一致率。
6. 多表连接重复聚合拦截率。

SQL执行成功不等于业务结果正确，最终验收以认证口径下的结果对账为准。
